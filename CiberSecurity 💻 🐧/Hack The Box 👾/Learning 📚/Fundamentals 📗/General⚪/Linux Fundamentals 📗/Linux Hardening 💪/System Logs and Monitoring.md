 There are several different types of system logs on Linux, including:
 - Kernel logs
 - System logs
 - Authentication logs
 - Application logs
 - Security Logs

# Kernel logs
These logs contain information about the system's kernel, including hardware drives, system calls and kernel events. You can see them with `journalctl -k`. For example, Kernel logs can reveal the presence of vulnerable or outdated drivers that could be targeted by attackers to gain access to the system

# System logs
These logs contain information about system-level events, such as service starts and stops, login attempts and system reboots. You can see them using `journalctl` + flag (search which flag because are so many)

# Authentication logs
These logs contain information about user authentication attempts, including successful and failed attempts. You can see them with `journalctl SYSLOG_FACILITY=4 -b` (or -f to follow)

# Application logs
These logs contain information about the activities of specific applications running on the system. You can see them using `journalct -u <service> -b`

# Security logs
In security, forensic analysis, and offensive security context, **security logs** are split into two categories: high-level access/authentication logs managed by systemd, and low-level kernel system-call audits managed by **`auditd`**.
### 1. High-Level Security & Access Logs (`journalctl`)
To analyze standard authentication events, session creations, and privilege escalation (such as `sudo` usage), query systemd's journal filtered by unit or process name:
```
# View privilege escalation events (sudo executions)
sudo journalctl _COMM=sudo -b

# View active user session logins and logouts (systemd-logind)
sudo journalctl -u systemd-logind -b

# View authentication failures across all services
sudo journalctl -b | grep -i "failed"
```

- **`_COMM=sudo`**: Filters log streams specifically generated by the **`sudo` binary execution**.
- **`-u systemd-logind`**: Tracks session allocations, TTY openings, and user logins. 
### 2. Granular Kernel Security Audits (`auditd`)
For deep forensic analysis, malware tracking, or monitoring specific file modifications (like changes to `/etc/passwd` or `/etc/shadow`), Linux uses the **Linux Audit Framework (`auditd`)**. Unlike systemd, `auditd` logs directly to plain-text files.
```
/var/log/audit/audit.log
```

Instead of using `cat` or `grep` on raw audit logs, use the native audit inspection utilities:
```
# Query audit logs for specific events using ausearch
sudo ausearch -m USER_LOGIN -i

# Generate a summary security audit report
sudo aureport --auth
```

- **`ausearch -m USER_LOGIN -i`**: Searches the audit log for user login events and translates numeric IDs (UIDs/GIDs) into human-readable text (**`-i`** / **`--interpret`**). 
- **`aureport --auth`**: Generates an aggregated summary report of all successful and failed authentication attempts recorded by the kernel.
