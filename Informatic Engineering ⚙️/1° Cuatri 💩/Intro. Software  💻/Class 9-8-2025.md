# Git
It's a system version controller that help us to handle and track the change made

## Git repositories
It's a space where the entire change history of a project is stored. It can be local repository, resides on our own computer, or remote repository, when the repository is located in a internet server like GitHub

## What is a commit?
A commit in Git is a snapshot of the sate of the files in our repository at specific point time

## Features
- It allow us to make branches of the project
- We can save history of version and go back them

## States
- Untracked
- Unstaged
- Staged
- Committed

### Untracked
Here we have these file that aren't tracked by GIT. To add these files, we use
```
git add <file>
```

### Unstaged
They are the file that was modified but aren't included in the next confirmation (`commit`). To confirm these one you use
```
git add <file>
```

### Staged
Here are those files ready to be confirmed. To confirm those files, we use
```
git commit -m "<message>"
```

### Committed
Here we have the file saved in our repository

## Basic commands
To create a repository:
```
git init
```

To download/clone a repository
```
git clone
```

### Info commands:
To see the local state:
```
git status
```

To see the difference between the changed you made and the repository without these changes:
```
git diff
```

To save temporarily uncommitted changes so we can switch branches or work in another one meanwhile
```
git stash
```

To return the last stash
```
git stash pop
```

To see all the stashes
```
git stash list
```

To see the history
```
git log
```

### Make change command
To change the state:
```
git add
```

To commit
```
git commit
```

Multi functional. It is a versatile Git command used to switch branches, create new branches, navigate commit history, and restore files
```
git checkout
```

To handle branch:
```
git branch
```

To pull change from a remote repository to a local repository
```
git pull
```

To push change from the local repository to the remote repository
```
git push
```
