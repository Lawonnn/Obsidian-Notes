## Requirements analysis
### What are we looking for?
- Understanding what the client or user want or need

- Understanding the scope
### What are we doing here?
 - Investigate
 - Negotiation
 - Specification
 - Validation

- Describe what the client want

- Define requirements that can be validated
## Design
### Choose an architecture
Based on the functionals and non-functionals requirements is very important to choose the right architecture: client-server, microservices, etc. Each one of these solve better some problem than others
## Implementation
Here is where we sit down to model the domain, design the data, write the code and ended up with something the user can use
## Testing and validation
### Aren't they the same thing?
- **Verification**: Are we building the **right** product?
- **Validation**: Are we building the **product** correctly?
### Reasons to test
- Show the client that the software fulfill all requirements (validation)
- Find functionable mistakes (verification)
- Inspire changes in requirements
### Types of tests
- Unit test
- Integration Test
- User Acceptance Test
- Usability testing
