# Docker
It's a tool that help us to manage the creation and deletion of containers
- Docker only run in Linux system. It run with the system kernel
- It solve the problem of running a specific program or a version of it without using a virtual machine
## Container
A container have the code and dependencies needed to run an application independently
## Image
The image has the instructions. It is defined in a file called `Dockerfile`
### Sequence:
- Each instruction in `Dockerfile` create an immutable layer. If two images share layers, Docker reuses them and doesn't waste duplicate disk space
- The container mounts a temporary layer on top. When the container is destroyed, any changes or new files disappear. If we want to save the data, we use the concept of `Volumes
- `Volumes`: folders on the Host disk securely linked to the container (key for databases or game worlds).
### Dockerfile
A **Dockerfile** is a text script containing sequential instructions used by the Docker engine to build an image.

#### Basic Structure
```
FROM <image>:<tag>
WORKDIR <path>
COPY <src> <dest>
RUN <command>
ENV KEY=VALUE
CMD <command/parameter(if ENTRYPOINT is defined)>
```
- `FROM`: Defines the base image. Search it in `Docker Hub`
- `WORKDIR`: Sets the absolute working directory inside the container
- `COPY`: Copies files/directories from the local host into the container
- `RUN`: Executes commands at build time
- `ENV`: Defines persistent environment variables
- `CMD`: Defines the default command executed when a container is launched via `docker run`
## Volumen
A reference of the container to the filesystem
## Container vs Image
### Image (The Plan)
- Static and **immutable template (read only)** .
- It's like **a house plan** (or a cooking recipe).
- It is defined with a `Dockerfile`.
### Container (The Built House)
- Live instance in **execution** of that image.
- It is **the house already built** from that plan.
- It has a state: it can be started, paused, stopped, and destroyed.

# Docker vs Virtual Machine
| **Category**                 | **Virtual Machines**                            | **Containers**                           |
| ---------------------------- | ----------------------------------------------- | ---------------------------------------- |
| **Underlying Concept**       | Hardware Virtualization                         | OS-Level Virtualization                  |
| **Abstraction Level**        | Virtualizes physical hardware                   | Virtualizes the operating system         |
| **Kernel Layer**             | Each VM runs its own dedicated **Guest Kernel** | All containers share the **Host Kernel** |
| **Software Implementations** | VMware Workstation, VirtualBox, KVM, Hyper-V    | Docker, Podman, LXC/LXD, containerd      |
